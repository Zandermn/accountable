Lesson 03 · Development tools

Understand the project toolbox

Learn what each tool installs, runs, or tracks. Then follow Accountable's setup without treating the commands as magic.

  • About 30 minutes
  • Prerequisite: Lessons 1–2
  • Setup requires internet once
The problem

The source is only text. Why can you not double-click main.tsx or main.py and get the whole app? Why does setup need two package managers?

Why it matters: Understanding the toolbox lets you recreate the same environment, choose the right command, and tell a missing dependency apart from an application bug.

01

Runtimes, packages, and lockfiles

Problem to solve

The app works on your computer but fails on another with a different package version. How can both computers run the code you intended?

The answer: Runtimes execute the languages, package managers supply dependencies, and lockfiles make the selected versions repeatable.

A runtime executes code. CPython executes Python. Node.js executes JavaScript outside a browser. Chrome's JavaScript engine executes frontend code inside the browser.

A dependency is a package that the project needs. A package manager installs compatible dependency versions and records them. Accountable uses:

npm for JavaScript

Reads package.json and package-lock.json. Installs into node_modules/.

uv for Python

Reads pyproject.toml and uv.lock. Installs into the local .venv/ environment.

A manifest such as package.json names direct dependencies and allowed version ranges. A lockfile records the resolved dependency tree. Use the lockfile for repeatable installs.

Package kindNeeded forExamples
Runtime dependencyRunning the applicationReact, FastAPI, SQLAlchemy, Chart.js
Development dependencyBuilding and testingTypeScript, Vite, Vitest, pytest, Playwright
Do not edit lockfiles by hand: Change the manifest with the package manager's normal workflow, then let that tool update the lockfile. Do not add a library just because it is popular. Check the existing manifests first.
02

Node.js, npm, and the workspace

Problem to solve

How can one npm command find the right frontend tools, start scripts, and work the same way on Windows, macOS, and Linux?

The answer: Node.js runs the scripts, npm runs named commands, and the workspace connects the root project with the frontend package.

Node.js runs the development scripts and frontend build tools. Accountable targets Node.js 26 and supports Node.js 24 or later. The browser runs the resulting frontend code; Node.js does not replace the browser.

npm is Node's package manager and script runner. The root package.json contains named scripts:

Simplified root package.json
{
  "workspaces": ["frontend"],
  "scripts": {
    "dev": "node scripts/dev.mjs",
    "test": "node scripts/test.mjs",
    "build": "npm run build --workspace frontend",
    "save": "node scripts/python.mjs -m backend.data_commands save"
  }
}

Run a script with npm run <name>. The command npm test is the short form for the special test script. The --workspace frontend option runs a script from the frontend workspace.

A workspace lets one repository contain related npm packages. Here, the root project controls shared commands and Playwright. The frontend workspace has its own frontend/package.json for React, Vite, TypeScript, and Vitest.

CommandUse
npm ciClean install from package-lock.json. Use this for first setup and automated checks.
npm installInstall and update dependencies during development. It can change the lockfile.
npm run buildType-check TypeScript and create production frontend files.
node --versionShow the installed Node.js version.

The folder node_modules/ contains installed packages. It is generated and ignored by Git. Delete it only when you have a reason and can reinstall it.

03

Python 3.12, uv, and .venv

Problem to solve

Another Python project on your computer needs different package versions. How can both projects work without changing each other's installation?

The answer: A virtual environment isolates Accountable's Python packages, and uv builds that environment from the project's manifest and lockfile.

Accountable requires Python 3.12. uv installs Python, manages packages, and creates the project environment. A virtual environment isolates this project's Python packages from other projects on your computer.

The root pyproject.toml uses TOML, a configuration format with sections and key-value pairs:

Simplified pyproject.toml
[project]
requires-python = ">=3.12,<3.13"
dependencies = [
  "fastapi>=0.115,<1",
  "uvicorn>=0.34,<1",
  "sqlalchemy>=2.0,<2.1",
  "openpyxl>=3.1,<4"
]

[dependency-groups]
dev = ["pytest>=8,<10", "httpx>=0.28,<1"]

The Python environment is .venv/. On Windows its interpreter is .venv/Scripts/python.exe. On macOS and Linux it is .venv/bin/python.

Accountable's scripts/python.mjs chooses the correct path. Root npm commands therefore use the same environment without requiring you to activate it manually.

Equivalent ideas
# Project command
npm run test:api

# What the script effectively runs
.venv/Scripts/python.exe -m pytest       # Windows
.venv/bin/python -m pytest               # macOS / Linux

The -m option runs a Python module. In the second command group, it runs pytest. In -m uvicorn backend.main:app, it runs Uvicorn and tells it where to find the FastAPI application.

04

Git and GitHub: history and collaboration

Problem to solve

A change breaks the app. Which exact lines changed, who changed them, and how can another person review the same work?

The answer: Git records diffs, commits, and branches locally. GitHub can host that history for review and collaboration.

Git tracks source history. A commit is a saved snapshot with a message and an ID. A branch is a movable name for a line of commits. The working tree is your current set of files.

GitHub hosts Git repositories online. It adds pull requests, reviews, issues, and automation. Git works locally without GitHub.

CommandPurposeChanges files or history?
git statusShow modified, untracked, and staged files.No
git diffShow unstaged line changes.No
git log --onelineShow commit history.No
git add <path>Stage selected changes for a commit.Staging only
git commit -m "Message"Create a commit from staged changes.Yes: local history
git switch <branch>Change the current branch.Yes: working tree
Protect existing work: Before you switch branches or reset anything, inspect git status. Do not use git reset --hard, force-push, or discard changes unless you understand and accept the data loss.

The .gitignore file lists paths that Git should not track. Accountable ignores generated dependencies, runtime data, and backups. Ignoring a file does not encrypt it. Never commit passwords, API keys, or secret configuration.

05

Accountable setup and daily commands

Problem to solve

How can you rebuild the app environment from an empty setup, then start it later when no internet connection is available?

The answer: One-time locked installs create local environments. The daily npm scripts use those installed tools directly instead of downloading them again.

Install Node.js 26, uv, and Google Chrome. Open a terminal in the repository root. With internet access, run:

One-time setup
uv python install 3.12
uv sync --locked
npm ci
  1. uv python install 3.12 makes the required Python version available.
  2. uv sync --locked creates or updates .venv/ to match uv.lock.
  3. npm ci installs JavaScript dependencies to match package-lock.json.

Start the app:

npm run dev

Open the URL printed by Vite, normally http://127.0.0.1:5173. The first launch creates data/accountable.db and adds sample data. Later launches open the existing database.

CommandResult
npm run devStart FastAPI and Vite together.
npm testRun Vitest, pytest, and Playwright. All suites run even after a failure.
npm run buildType-check and build the frontend into frontend/dist/.
npm run saveSave a complete JSON backup and print its ID and path.
npm run load -- <backup-id>Save current data, then load the selected backup.
npm run seedAfter confirmation and a backup, replace the dataset with samples.
Replacement commands: load and seed replace active records and Trash. They automatically save the current state first. Keep the printed backup ID. Do not use these commands as casual experiments on data you need.

After setup, startup and normal use work offline. They use installed dependencies and local fonts. Initial downloads and dependency updates still need internet.

06

Environment variables and ports

Problem to solve

How can browser tests use temporary databases and free ports without editing the app's configuration files before every test?

The answer: Environment variables pass process-specific paths and ports. Tests set temporary values while your normal defaults stay unchanged.

An environment variable is a named value supplied to a process. Accountable reads these optional settings:

VariableDefaultPurpose
ACCOUNTABLE_DBdata/accountable.dbDatabase file path.
ACCOUNTABLE_BACKUPSdata/backups/Backup directory.
ACCOUNTABLE_PORT5173Frontend port.
ACCOUNTABLE_API_PORT8000Backend port and Vite proxy target.

Tests set temporary database and backup paths and free ports. This keeps test data separate from your data. Use the same database and backup settings for the app and its data commands.

An editor such as VS Code helps you search files and read syntax highlighting. It is useful, but it is not a runtime. The terminal commands define the actual setup.

07

Check your understanding

1. Why are there two package managers?

The project has two language ecosystems. npm manages JavaScript and frontend tools. uv manages Python and backend tools. Root npm scripts coordinate both.

2. Why use npm ci and uv sync --locked for setup?

They install from lockfiles. This gives every developer and test run the same resolved dependency versions.

3. Does npm run dev download packages each time?

No. The script starts the installed backend and frontend tools directly. Offline startup is a project requirement.

4. Is .venv/ source code?

No. It is a generated, local Python environment. The source manifests and lockfiles describe how to recreate it.
