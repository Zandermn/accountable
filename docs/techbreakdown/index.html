Start with a real problem

You click Save and a contact appears. But where did it go? Why can you refresh without losing it? And what would you check if it disappeared?

Why this course matters: When you understand the path from a click to a saved database row, you can use the app with confidence. You can find the cause of problems, make safer changes, and judge whether a coding agent's suggestion makes sense. You will not need to guess or memorize commands without understanding them.

Who this course is for

This course is for a beginner who wants to understand the Accountable repository. You do not need to know how to code. You will learn one idea at a time and then see that idea in the project.

Read first: This tutorial explains the current local CRM. Sign-in, Supabase, and Render are future options in docs/TECH_STACK.md. They are not part of the current application.

Use a laptop or desktop if possible. Open the tutorial and the project folders side by side. You can read every lesson without installing anything. The practical lessons use the tools listed in docs/STATUS.md.

THE BIG PICTURE

One application, three main layers

The first design puzzle

Why does Accountable need React, FastAPI, and SQLite instead of one giant program that does everything?

The answer: Each layer solves a different problem: presenting the interface, enforcing the rules, and preserving the data. The course reveals how they cooperate.

Accountable runs on your computer. Your browser shows the interface. A local Python program applies rules and manages data. SQLite stores the records in a file.

  1. React in your browser
  2. FastAPI on localhost
  3. SQLite database file

How to use each lesson

  1. Read the question first. Imagine what you would try. Then read the answer and compare it with your prediction.
  2. Read the goals. They tell you what you should be able to explain at the end.
  3. Run the small examples. Change one value and predict the result before you run it again.
  4. Open the named project files. You do not need to understand every line. Find the pattern shown in the lesson.
  5. Try the questions before you open the answers. A wrong prediction is useful feedback.
  6. Use the quick reference later. You do not need to memorize commands or terms.
Keep your data safe: Read-only exercises are safe. Commands such as npm run seed and npm run load replace the current dataset. The app saves a backup first, but you must still read each command before you run it.
