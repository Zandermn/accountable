Start with a real problem

A coding agent says, “Done.” A contact appears after Save. Is that enough evidence to merge the change?

Why this course matters: A visible success is only one observation. You need to know the requested behavior, the code path, the failure cases, and the checks that ran. This course teaches you to build that chain of evidence, with or without an agent.

Who this course is for

This course is for a beginner who wants to understand Accountable and for a developer who wants to direct coding agents with care. Lessons 1–8 explain the running product. Lessons 9–11 explain how this repository changes that product safely. Lesson 12 joins both parts in a practical capstone.

Read the current product first: docs/spec.md is the source for current behavior. Accountable now includes light and dark modes. Sign-in, Supabase, hosted access, and Render deployment remain future options, not current features.

Use a laptop or desktop if possible. Open the tutorial and the project folders side by side. You can read every lesson without installing anything. Practical work uses the setup in docs/STATUS.md.

THE BIG PICTURE

One product, three runtime layers, one delivery system

The design puzzle

Why does Accountable need React, FastAPI, and SQLite—and why are specifications, reviews, and hooks also part of the engineering design?

The answer: Runtime layers control what the product does. The delivery system controls how changes reach it. Both need clear boundaries and evidence.

How to use each lesson

  1. Predict before you read the answer. A wrong prediction shows which mental model needs work.
  2. Open the named source. Follow one path through real files instead of trying to memorize a folder tree.
  3. Separate fact from inference. A specification states required behavior. A test reports observed behavior. Neither proves every untested case.
  4. Run small experiments safely. Use temporary test data. Read commands before you run them.
  5. Practice the agent loop. Give context, inspect the diff, question assumptions, and require evidence.
  6. Use the quick reference later. Understanding the route matters more than memorizing every command.
Keep data and secrets safe: npm run seed and npm run load replace the current dataset after a backup. Never paste secret configuration or real customer backups into an agent prompt. Keep all .env files unchanged unless the project owner explicitly handles them.
