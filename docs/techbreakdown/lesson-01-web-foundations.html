How a web application works

Learn the words for the files, programs, and messages that make up Accountable.

  • No setup needed
  • About 25 minutes
  • Prerequisite: none
The mystery

You open Contacts on your own computer. Why does that simple click involve a browser, two servers, and a database?

Why it matters: Knowing who does each job gives you a map. When a page cannot load or data cannot save, you will know where to look instead of guessing.

01

Source files and folders

Problem to solve

If an app is only a collection of files, how does your computer know which files to run, which ones to display, and which one contains your customer data?

The answer: Paths and file formats give every resource a location and a job. Learning to read them turns an intimidating folder tree into a usable map.

A file is a named collection of data. A folder, also called a directory, groups files and other folders. A path gives a file's location.

This project is a repository, or repo: a project folder whose history is managed by Git. The repository root is the top project folder. It contains package.json, pyproject.toml, and the frontend/ and backend/ folders.

accountable/ ← repository root ├── frontend/ ← browser application │ └── src/main.tsx ← frontend entry point ├── backend/ ← Python application │ └── main.py ← backend entry point ├── data/accountable.db ← saved records └── docs/techbreakdown/ ← this course

02

The terminal: text commands for your computer

Problem to solve

What if you need to start two programs, watch their errors, and stop both—but the app has no Start button for developers?

The answer: A terminal gives you direct control over commands and processes. It also shows the diagnostic messages that a graphical interface may hide.

A terminal lets you type commands instead of clicking a graphical interface. A shell reads those commands. PowerShell, Command Prompt, and Git Bash are shells available on Windows. macOS and Linux have their own shells.

The shell has a working directory. Relative paths start from that directory. Project commands normally run from the repository root.

Common navigation commands
pwd       # Print the working directory in Git Bash, macOS, and Linux
cd path   # Change to a folder
cd ..     # Move to the parent folder

To list files, use ls in Git Bash, macOS, or Linux. Use dir in PowerShell or Command Prompt. A # starts a comment in the shell examples above; the shell does not run that explanation.

Be careful: A terminal command can change or remove files immediately. Check the working directory and the command before you press Enter. Do not run a command that you do not understand.

A process is a running program. Accountable starts two server processes. Keep their terminal open while you use the app. Press Ctrl + C to ask them to stop.

03

Browsers, clients, and servers

The mystery

If the browser, frontend, backend, and database all run on one computer, why do you still need something called a server?

The answer: Client and server describe roles, not physical locations. One computer can host programs that request and provide services to each other.

A browser such as Chrome displays web pages and runs browser JavaScript. A client requests a service. A server provides that service. These are roles, not always separate computers.

In Accountable, the browser and both servers run on the same computer:

  1. Browser asks Vite for the app
  2. Browser asks FastAPI for data
  3. FastAPI reads SQLite
  • Vite serves the frontend files while you develop.
  • Uvicorn runs the FastAPI backend.
  • SQLite is a database engine. It is a library used by the backend, not a separate server process.

The browser can request a page, a CSS file, a font, or JSON data. A program can also be a client. The tests use an HTTP client to call the backend without a browser.

04

URLs, hosts, ports, and paths

The mystery

Vite and FastAPI share the same computer. When a request arrives, how does the computer know which program should answer?

The answer: A URL separates the host, port, path, and query. The port selects the process; the remaining parts identify the resource and options.

A URL is an address for a resource. Accountable normally opens this URL:

http://127.0.0.1:5173/contacts?status=Lead
└┬─┘   └────┬────┘ └┬┘ └──┬──┘ └─────┬─────┘
scheme     host    port   path       query
PartMeaning
SchemeThe protocol. HTTP is the web's request-and-response protocol.
HostThe computer. 127.0.0.1 and localhost mean this computer.
PortA numbered endpoint for a process. Vite normally uses 5173. FastAPI uses 8000.
PathThe requested resource or application view, such as /contacts.
QueryExtra parameters after ?. Here, the app filters contacts by Lead status.

Loopback means network traffic that stays inside your computer. Accountable binds both servers to 127.0.0.1. This limits access to the local computer. It does not add user authentication.

Two different URL jobs: /contacts is a frontend route that shows a React view. /api/records/contacts is a backend endpoint that returns contact data.
05

HTTP messages and JSON data

The mystery

Browser JavaScript and backend Python do not share variables. How can the browser ask Python to create a contact and understand whether it worked?

The answer: HTTP supplies the request-response envelope, methods express the operation, status codes express the outcome, and JSON carries structured data.

An HTTP request asks a server to do something. The server returns an HTTP response. A request has a method and URL. It can also have headers and a body. A response has a status code, headers, and often a body.

MethodTypical jobAccountable example
GETRead dataLoad contacts
POSTCreate data or start an operationCreate a contact or move a card
PATCHChange selected fieldsEdit a deal
DELETERemove a resourceMove a record to Trash or delete a backup

Success responses normally use a 2xx status. Accountable uses 404 for an unavailable record, 409 for a conflict with current data, and 422 for invalid input.

JSON (JavaScript Object Notation) is a text format for structured data. It supports objects, arrays, strings, numbers, booleans, and null.

A simplified contact response
{
  "id": "contact-123",
  "name": "Amina Yusuf",
  "status": "Lead",
  "organization_id": null,
  "email": "amina@example.com"
}

An API (Application Programming Interface) is a defined way for software to communicate. Accountable's backend has a JSON HTTP API. The frontend does not read the SQLite file directly.

The frontend sends JSON with a Content-Type: application/json header. For workbook upload it sends form data instead. See frontend/src/data.tsx for the shared api() function.

06

Frontend, backend, and database

Design puzzle

Why not let the browser open the SQLite file and save whatever it wants? That would need fewer moving parts, but what rules would it bypass?

The answer: Separate layers give each job a controlled boundary. The browser presents, the backend validates and coordinates, and the database persists valid rows.

Frontend

The part in the browser. It displays controls, keeps temporary screen state, and asks the API for saved data.

React · TypeScript · Vite

Backend

The Python process. It checks input, applies sales rules, performs calculations, and controls transactions.

FastAPI · Uvicorn · services

Database

The persistent store. Records stay available after a refresh or restart.

SQLite · SQLAlchemy Core

Full-stack describes work across these layers. Persistence means data remains after the program stops. A React state value is temporary. A committed SQLite row is persistent.

A complete example

  1. You type a contact name in a React form.
  2. The browser sends a POST request to /api/records/contacts.
  3. FastAPI sends the request to the record service.
  4. The service validates the fields and inserts a row through SQLAlchemy.
  5. The transaction commits. SQLite writes the change to data/accountable.db.
  6. The API returns the saved contact as JSON. React refreshes the affected views.
07

Check your understanding

1. Is SQLite the same thing as FastAPI?

No. FastAPI handles HTTP requests and routes them to Python functions. SQLite stores and retrieves database rows. SQLAlchemy Core helps the Python code communicate with SQLite.

2. Why does the frontend use an API instead of opening the database file?

The API gives the app one controlled place for validation, business rules, transactions, and response shapes. The browser cannot safely apply those backend rules on its own.

3. What do 5173 and 8000 identify?

They are port numbers. They let the browser reach the correct server process on the same host.

Optional observation: In Chrome, press F12 and open the Network panel. Reload any website. Each row is a request. Select one to inspect its URL, status, headers, and response. Lesson 9 repeats this with Accountable.
