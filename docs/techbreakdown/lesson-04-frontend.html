Build the browser interface

The mystery

Why it matters: Once you understand components, state, and requests, the interface stops feeling magical. You can trace a visible problem back to the component that owns it.

01

HTML, CSS, JavaScript, and the DOM

Problem to solve

How does the browser know that Save is a button you can activate, not just green text that happens to look clickable?

The answer: HTML supplies meaning and behavior, CSS supplies appearance, and JavaScript changes the live DOM when something happens.

These browser technologies have different jobs:

  • HTML defines structure and meaning: headings, buttons, forms, tables, and links.
  • CSS controls presentation: color, spacing, layout, and responsive behavior.
  • JavaScript controls behavior: events, requests, calculations, and page updates.
Small HTML and CSS example
<button class="primary">Save contact</button>

<style>
  .primary {
    background: #06D6A0;
    color: #073B4C;
    border-radius: 8px;
  }
</style>

The browser parses HTML into the DOM (Document Object Model), a live tree of objects. JavaScript can read and change this tree. React manages many of those changes for the app.

An HTML element has a tag and can have attributes. For example, aria-label="Search contacts" gives a control an accessible name. Semantic elements such as <button> and <table> provide useful browser behavior.

Accountable's styles are custom CSS in frontend/src/style.css. There is no CSS framework. The file defines brand variables, grid layouts, cards, dialogs, tables, keyboard focus, and screen-size rules. Fonts are bundled in frontend/public/fonts/ for offline use. Lucide icons are bundled through the installed lucide-react dependency.

Design tokens and saved themes

A design token is a named visual value such as a surface or text color. Shared CSS tokens let panels, dialogs, Pipeline, and charts use the active light or dark palette instead of duplicating component styles.

frontend/src/theme.tsx owns the shared Theme control. It reads the preference through GET /api/preferences/theme and saves with PUT. The backend stores the choice in SQLite, so another browser on the same computer can read it. Light is the default until the user selects a mode; the device's theme setting does not choose for the app.

The frontend applies the selected theme immediately, but a timeout has uncertain completion. Read deadlines, save recovery, and protection from late responses prevent a stalled request from trapping the workspace. Lesson 11 walks through that failure case.

02

TypeScript: JavaScript with type checks

Problem to solve

What if you type deal.value when the real property is value_cents? Would you prefer to discover that during development or after a user clicks?

The answer: TypeScript checks value shapes before execution. It catches many mismatches early, while backend validation handles untrusted runtime data.

TypeScript adds static types to JavaScript. Static means the tool checks types before the program runs. TypeScript can catch a misspelled property or a wrong value shape during development.

Types for a deal
type Deal = {
  id: string;
  name: string;
  value_cents: number;
  late: boolean;
  organization_id: string | null;
};

function expectedRevenue(deal: Deal, probability: number): number {
  return deal.value_cents * probability / 100;
}

string | null is a union type: the value can be a string or null. An interface is another way to describe an object shape. Accountable uses both type and interface.

TSX lets TypeScript contain React UI expressions. Browsers do not execute TypeScript or TSX directly. Vite transforms them into JavaScript for development and production.

Types do not validate HTTP data at runtime: A TypeScript annotation disappears in the generated JavaScript. The Python backend must still validate every request. This is why both sides have checks with different jobs.

The frontend uses strict checking in frontend/tsconfig.json. It targets ES2022, a JavaScript language version, and includes DOM types for browser APIs. npm run build runs tsc --noEmit: type-check without writing JavaScript from tsc itself. Vite then builds the app.

03

React components, props, and rendering

Design puzzle

Seven views need the same navigation, buttons, record rows, and dialogs. Do you copy their HTML into every page?

The answer: React components package reusable UI and behavior. Props customize them, and rendering updates the DOM when their inputs change.

React 19 builds an interface from components: reusable functions that return UI descriptions. A component can contain other components. Props are inputs passed from a parent component.

A small TSX component
type BadgeProps = { label: string; late: boolean };

function Badge({ label, late }: BadgeProps) {
  return <span className={late ? 'late' : 'status'}>{label}</span>;
}

export function DealName() {
  return (
    <article>
      <h2>Renewal</h2>
      <Badge label="Late" late={true} />
    </article>
  );
}

TSX looks like HTML but uses JavaScript expressions inside braces. It uses className for a CSS class. A parent passes label and late as props.

React renders components to work out what the DOM should contain. When state or props change, React renders again and updates the necessary DOM. A list item needs a stable key, usually the record ID, so React can match items between renders.

The application's entry point
createRoot(document.getElementById('root')!).render(
  <BrowserRouter>
    <App />
  </BrowserRouter>
);

frontend/index.html provides <div id="root">. frontend/src/main.tsx mounts React there. App.tsx creates the navigation shell. Workspace.tsx selects the current view.

04

State, events, effects, and context

Problem to solve

What should the screen remember while you type a note, wait for the API, open a dialog, or switch to another deal?

The answer: State remembers changing values, events react to users, effects synchronize requests and timers, and context shares session values across components.

State is data that a component remembers between renders. Examples include search text, a selected deal, an open dialog, and a busy flag.

A controlled search input
const [search, setSearch] = useState('');

<input
  type="search"
  value={search}
  onChange={(event) => setSearch(event.target.value)}
/>

useState returns the current value and a setter. Calling the setter requests a render. The input is controlled because React state supplies its value and its change event updates that state.

Hook or toolJobAccountable example
useStateRemember local component state.Search, form drafts, dialog state.
useEffectSynchronize with something outside React.Fetch data, listen for window focus, start a timer.
useContextRead shared values without passing every prop.Session dataset, refresh function, record commands.
useRefKeep a mutable value without causing a render.Remember dragged card or focus target.
useCallbackKeep a function reference stable between renders.The shared refresh function.

The custom useRead() hook in frontend/src/data.tsx calls the API when its path or refresh epoch changes. Its effect cleanup marks an old request inactive. This prevents an old response from updating a view after the request is no longer relevant.

Events connect users to logic. A form onSubmit calls preventDefault() to stop a full browser page submission, then sends JSON through the API. A failed request keeps entered values and shows an error. A successful write calls the shared refresh function.

Temporary versus saved: React state can hold an unsaved note draft. Only a successful backend write makes the note persistent in SQLite.
05

React Router and API requests

Problem to solve

How can you open or share a link to one deal without reloading the whole application or losing the selected view?

The answer: React Router maps URLs to views and updates them in the browser. The shared API helper separately retrieves that deal's saved data.

React Router keeps the visible view synchronized with the browser URL. Accountable uses BrowserRouter, Link, NavLink, useLocation, and useNavigate.

URLSelected UI
/Dashboard and embedded pipeline
/organizations, /contacts, /dealsSearchable and sortable directories
/deals/<id>Deal workspace with notes and timeline
/pipeline?deal=<id>Board with the selected deal panel
/trash, /dataRecovery and data tools

This is client-side navigation. Clicking a React link changes the URL and renders another view without loading a whole new HTML document.

The shared generic function api<T>() in data.tsx wraps fetch():

  • Adds /api to the endpoint path.
  • Serializes ordinary bodies with JSON.stringify().
  • Leaves FormData intact for workbook uploads.
  • Adds the X-Dataset header when supplied.
  • Parses the JSON response and throws a Failure for an error status.

IDs are encoded before they go into a URL. The idSegment() and segmentId() helpers also protect unusual workbook IDs that contain slashes or reserved path text.

06

Vite: development server, proxy, and build

Problem to solve

The frontend is on port 5173 and the API is on 8000. How can browser code simply call /api/dashboard without managing two origins?

The answer: Vite serves the frontend and forwards API paths to FastAPI. It also transforms TSX for development and bundles optimized production files.

Vite transforms frontend source and serves it during development. It supports fast updates and produces optimized static files for production.

During local development, the browser uses one origin, normally http://127.0.0.1:5173. Vite proxies paths beginning /api to FastAPI at http://127.0.0.1:8000. A proxy forwards a request to another server.

  1. Browser: /api/dashboard
  2. Vite proxy on port 5173
  3. FastAPI on port 8000

This gives the frontend same-origin API URLs and avoids browser cross-origin configuration. The setting is in frontend/vite.config.ts. ACCOUNTABLE_API_PORT can change the target.

Build command chain
npm run build
→ npm run build --workspace frontend
→ tsc --noEmit && vite build
→ frontend/dist/

frontend/dist/ is generated output, not the source you edit. The current local workflow normally uses npm run dev. The build command is also a useful type and bundling check.

07

Charts, pipeline movement, and accessibility

Design puzzle

A chart looks clear and a card moves easily with a mouse. What happens if someone cannot see the colors or uses only a keyboard?

The answer: Text values, semantic labels, visible focus, and the Move dialog provide equivalent paths. Chart.js and native drag events supply the visual and pointer interactions.

Chart.js and react-chartjs-2

Chart.js draws charts on an HTML canvas. react-chartjs-2 supplies React wrappers. Dashboard.tsx registers only the chart pieces it needs, then uses Line for won revenue and Bar for monthly wins. A <details> element also exposes the monthly values as text.

Native drag and drop plus keyboard controls

The pipeline uses browser drag events in Sales.tsx. A card stores its ID with dataTransfer. Drop logic calculates the target stage and the card before which it belongs. The Move button opens a form with stage and position controls. This provides a keyboard path for the same operation.

The frontend sends the target placement and board revision to POST /api/pipeline/move. The backend owns the saved order. The frontend refreshes after success or failure so the display returns to the saved state.

Accessibility

Accessibility means people can use the app with different abilities and input methods. Accountable uses labels, semantic buttons, visible focus, dialog focus management, status text, and keyboard movement. Color is not the only signal for Late or Overdue.

WCAG is the Web Content Accessibility Guidelines. This project checks AA text contrast in both themes: at least 4.5:1 for normal text and 3:1 for large text. Chart labels need the same attention as ordinary controls. Automated tests help, but visual and keyboard inspection remains necessary.

Try without a mouse: In the running app, press Tab to move between controls. Use Enter or Space to activate buttons. On a pipeline card, open Move and inspect the stage and position fields.

09

Check your understanding

1. What is the difference between a prop and state?

A prop comes from a parent component. State belongs to a component or its shared state system. Both can cause rendering when their values change.

2. Does TypeScript replace backend validation?

No. It checks frontend source before execution. A request can contain any data, so the backend performs runtime validation.

3. Why does Vite proxy /api?

It lets the browser call the same origin as the frontend while Vite forwards API requests to the separate FastAPI process.

4. Why does the board need a non-drag control?

Drag-only interaction excludes keyboard users and can be difficult for other users. The Move dialog provides equivalent stage and position controls.
