01

FastAPI and Uvicorn

Problem to solve

A request arrives at port 8000 for /api/dashboard. How does that network message reach the right Python function?

The answer: Uvicorn accepts the HTTP connection, while FastAPI matches the request to a route and returns the function's response.

FastAPI is a Python web framework. It connects URL paths and HTTP methods to Python functions. Uvicorn is the server that accepts network connections and runs the FastAPI application.

Started by scripts/dev.mjs
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000

backend.main:app means “find the variable app in backend/main.py.” The host is loopback, so the server listens on this computer.

backend/main.py defines an application factory called create_app(). A factory builds and configures an application. Tests call it with a temporary database and no sample seed.

Simplified application setup
def create_app(database=None, seed=True):
    @asynccontextmanager
    async def lifespan(app):
        app.state.store = Store(database, seed)
        yield
        app.state.store.engine.dispose()

    app = FastAPI(lifespan=lifespan, docs_url=None, redoc_url=None)
    app.include_router(record_routes)
    app.include_router(sales_routes)
    app.include_router(workbook_routes)
    app.include_router(backup_routes)
    return app

The lifespan runs startup and shutdown work. Startup creates the Store, which opens or initializes the database. Shutdown disposes database connections. The yield separates those phases.

No Swagger page: FastAPI can generate interactive API documentation. This app disables /docs and /redoc. Use the endpoint reference in Lesson 6 and the real app for exploration.
02

Routes, parameters, and JSON responses

Problem to solve

The URL contains a record ID, the query contains search text, and the body contains fields. How does one Python function receive all three?

The answer: FastAPI maps path, query, header, and body values into function parameters. Returned dictionaries become JSON responses.

A route matches an HTTP method and path. FastAPI decorators such as @router.get() register routes. An APIRouter groups related routes before the main app includes them.

Simplified from backend/api/records.py
router = APIRouter(prefix="/api")

@router.get("/records/{kind}")
def listing(request: Request, kind: str, search: str = ""):
    with request.app.state.store.read() as conn:
        return records.listing(conn, kind, search)

@router.patch("/records/{kind}/{record_id}")
def edit(request: Request, kind: str, record_id: str,
         body: dict, x_dataset: int = Header()):
    with request.app.state.store.write(x_dataset) as conn:
        return records.save(conn, kind, body, path_id(record_id))
Function inputWhere the value comes from
kind, record_idPath parameters in the URL.
searchA query parameter, with an empty-string default.
body: dictThe JSON request body as a Python dictionary.
x_datasetThe X-Dataset request header.
requestThe current HTTP request and app state.

Returning a dictionary or list makes FastAPI serialize it as JSON. The shared Problem exception carries an error status and details. A handler in main.py turns it into a JSONResponse.

The API modules are thin. They read request values, choose a read or write transaction, and call a service. They do not duplicate all sales rules.

03

Service modules and business rules

Design puzzle

A deal can change stage from a form, a board move, or a workbook. What stops each path from applying a different probability rule?

The answer: All paths call the same backend service. Routes translate HTTP; services own the business rules and keep every entry point consistent.

A service contains application operations and business rules. Accountable uses the same services for browser writes, workbook imports, and local commands. This keeps behavior consistent.

API layer

Understand HTTP. Route the request and return a response.

backend/api/

Service layer

Validate fields, apply record rules, calculate totals, and coordinate changes.

backend/services/

Database layer

Define tables, open connections, control transactions, and store rows.

backend/db/

Examples of business rules in backend/services/records.py:

  • Trim names and reject blank names.
  • Require a valid contact status and valid supplied email.
  • Require an active organization, main contact, or both for every deal.
  • Apply the destination stage's default probability when a stage changes.
  • Require an expected close date for an open deal.
  • Give an activity exactly one owner and normalize its timestamp to UTC.

The save() function handles create and edit. It rejects unknown fields, loads old values for an edit, validates the combined state, and uses either insert() or update(). A stage change also inserts an event for the timeline.

services/sales.py owns board ordering and dashboard calculations. services/trash.py owns deletion and recovery. services/backups.py owns snapshots and replacement. services/workbooks.py owns spreadsheet parsing and atomic imports.

04

SQLAlchemy Core and SQLite

The mystery

How does a contact survive after you close the browser and stop Python—and how can the app query it without handwritten SQL strings?

The answer: SQLite stores persistent relational rows in a file. SQLAlchemy Core defines tables and builds safe query expressions in Python.

SQLite stores a relational database in one local file. SQLAlchemy Core is a Python toolkit for defining tables and building SQL statements. Accountable uses Core table objects and expressions. It does not use ORM model classes, and project queries do not contain handwritten SQL strings.

Simplified table definition
contacts = Table(
    "contacts",
    schema,
    Column("id", String, primary_key=True),
    Column("name", String, nullable=False),
    Column("organization_id", String,
           ForeignKey("organizations.id")),
)

A primary key uniquely identifies a row. A foreign key references a row in another table. nullable=False rejects a missing value. A check constraint enforces a rule such as nonnegative deal value or exactly one activity owner.

Build and execute a query
statement = (
    select(contacts)
    .where(contacts.c.deleted_at.is_(None))
)
rows = conn.execute(statement).mappings().all()

contacts.c gives access to columns. select() builds a query. The connection executes it. .mappings() makes rows available by column name.

The Store enables SQLite foreign-key enforcement on every connection. It uses a 15-second connection timeout and explicit transactions. The default file is data/accountable.db. Do not edit this binary file with a text editor.

05

Transactions, revisions, and conflicts

Problem to solve

A move updates two pipeline columns. What if the first update succeeds but the second fails? What if the board changed after you opened the Move dialog?

The answer: Transactions make related changes atomic. Revision and dataset checks reject stale actions before they overwrite a newer state.

A transaction groups database work into one atomic unit. Atomic means all changes commit or none do. A commit saves the unit. A rollback undoes its uncommitted changes.

Simplified write context manager
with store.write(dataset) as conn:
    records.save(conn, "contacts", fields)
    # More related changes can happen here.
# Successful exit commits. An exception rolls back.

The real Store.write() first takes SQLite's write lock. It then checks optional revision values before yielding the connection. On success, it advances the dataset revision. This prevents two related writes from exposing a half-finished state.

Version valueWhat it detects
revisionData changed since a board read or deletion preview.
datasetA backup load or sample reset replaced the whole dataset.

If a check fails, the API returns 409 Conflict. The user must review the latest state instead of overwriting it with a stale action. The frontend polls /api/version every three seconds and on window focus.

Workbook preview uses a nested transaction, also called a savepoint. It runs all proposed changes and then rolls back that nested unit. Apply runs the same validation and commits the unit only when the token still matches the workbook and database revision.

06

Workbooks and supporting packages

Problem to solve

An uploaded workbook is a ZIP of XML with formulas, types, and links. How can the app use it without trusting every cell or expanding it without limit?

The answer: openpyxl parses the format, multipart handles uploads, and size, formula, type, and value checks reject unsafe or invalid input.

An .xlsx file is a ZIP archive containing XML and other workbook data. openpyxl reads and writes these files. Accountable uses it to create templates and exports and to parse imports in read-only mode.

The backend also has these supporting dependencies:

PackageRole
python-multipartLets FastAPI accept multipart form uploads for the workbook file and token.
defusedxmlSupports safer XML processing for libraries that parse XML, including workbook processing.
Python zipfileChecks the total expanded size before openpyxl parses the workbook.
Python DecimalConverts dollar decimals to exact integer cents and rejects invalid precision.
Python hashlibCreates workbook preview tokens and backup checksums.

Uploads are limited to 16 MB. Expanded workbook content is limited to 64 MB. Formula cells are rejected. Errors identify the sheet, row, and field. Lesson 6 explains the complete preview and apply flow.

08

Check your understanding

1. What is the difference between FastAPI and Uvicorn?

FastAPI defines application routes and request handling. Uvicorn runs the server that receives HTTP traffic and passes it to that application.

2. Why keep business rules out of route functions?

Shared services let browser routes, workbook imports, and local commands apply exactly the same rules. Tests can also exercise services directly.

3. Is SQLAlchemy Core an ORM here?

No. The project uses table definitions and SQL expression objects, not ORM entity classes. It also avoids raw SQL strings.

4. Why does a failed workbook preview not add records?

The preview runs inside a nested transaction and rolls it back. Apply uses a matching token and commits only after all rows pass validation.
